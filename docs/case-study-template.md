# Case study template

Use this structure for a lab, design exercise or approved professional case. Label the type at the top. Replace all operational information with independently created synthetic material before publication.

## Problem and scope

Describe the service, security objective, constraints and business impact without naming an organization, customer, real asset or environment identifier.

## Contribution and provenance

State what you personally assessed, designed, implemented or tested. Separate original work from a course, third-party component or proposed extension. Link public source commits where appropriate.

## Evidence and uncertainty

List the sanitized artifacts that support each finding. State the collection method, evidence limits, assumptions and alternative explanations. Do not include original incident evidence or raw logs.

## Decisions and controls

Explain the threat, priorities, treatment alternatives, least privilege, observability, ownership and recovery approach. Explain why each selected control addresses the identified risk.

## Validation and result

Include reproducible lab commands or an approved test method, expected and observed outcomes, limitations and residual risk. Report metrics only when supported by shareable evidence. Mark unexecuted tests as a plan.

## Lessons and next step

State what worked, what needs further validation and what would be required for a production implementation.

## Publication review

Apply the [publication standard](publication-standard.md), including repository history, screenshots, metadata, permissions and third-party rights. If safe publication cannot be established, publish a new synthetic exercise instead.
